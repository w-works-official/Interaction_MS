# 반응형 원본 스킨 적용용 사본

원본 `C:/2026_Work/Makeshop/반응형`의 14개 파일은 변경하지 않습니다. 이 폴더는
그 원본을 UTF-8로 보관하고, PC·모바일의 같은 콘텐츠를 두 번 설정하던 부분을
공통 설정으로 연결한 **복사 스킨 검수용 사본**을 생성합니다. 메이크샵 저장,
대표 디자인 변경, Cloudflare 배포를 자동으로 수행하지 않습니다.

## 한 번 수정하는 원본

- `../dist/storefront.js`: 브랜드, 메뉴 이름·링크, 원본 메인 배너 네 장,
  카테고리 타일, 문의 링크입니다. 외부 고객 프론트와 네이티브 사본이 이 소스를
  함께 사용합니다. 네이티브 전용 하위 분류·게시판은 같은 설정의 별도 항목입니다.
- `../dist/storefront.css`: 새 공통 구성의 스타일입니다. 네이티브에서는 지정한
  `.shop-view` 구성 안에만 적용합니다. 기존 상품·옵션·사업자 정보 CSS는 보존합니다.
- `runtime.js`, `overrides.css`: 메이크샵 네이티브 페이지의 연결 코드입니다.
  여기에는 상품 가격·상품 사진 목록·계정 데이터를 저장하지 않습니다.
- `apply/`는 생성 결과입니다. 이 파일만 직접 수정하면 다음 생성 때 덮어씁니다.

동일 배너를 모든 폭에서 사용하는 것이 기본입니다. 다른 크롭이 반드시 필요한
경우에만 `mobileImage`를 추가하면 `<picture>`의 선택 소스로 사용합니다. 단순히
모바일이라는 이유로 이미지나 문구를 두 벌 등록하지 않습니다.

설정 파일을 수정한 뒤 재생성해 적용하는 흐름입니다. 운영자 화면의 localStorage
공개 버튼이 메이크샵이나 다른 방문자의 설정을 실시간 변경하는 기능은 아닙니다.
공용 DB·시트·Auth·서버 연결을 추가하지 않았습니다.

## 생성

저장소 루트에서 실행합니다. Python 표준 라이브러리만 사용합니다.

```powershell
python -B integration-responsive/build.py --native-platform pc
```

원본 경로를 바꿀 경우 `--source-dir "절대경로"`, 별도 산출물 위치는
`--output-dir "절대경로"`를 명시합니다. 출력은 원본 디렉터리 안에 만들 수 없습니다.
입력 CP949는 **사본만 UTF-8/LF로 변환**합니다. `SOURCE_MANIFEST.json`에 원본 바이트
SHA-256, 원래 인코딩, UTF-8 보관본과 적용본의 SHA-256을 기록합니다.

`source-utf8/`는 원본 내용의 UTF-8 보관본이고 `apply/`는 변경된 14개 파일입니다.
기존 `outputs/`의 다른 파일은 수정하거나 삭제하지 않습니다.
원본 Windows 폴더가 없는 CI·다른 컴퓨터에서는 보관된 `source-utf8/`를 사용하며,
manifest의 보관본 SHA-256이 일치할 때만 생성합니다. 원래 CP949 바이트의 SHA와
출처 기록은 그대로 유지합니다. 보관본이 변경되면 생성하지 않고 오류를 냅니다.

반응형 한 스킨의 네이티브 상세 경로를 아직 서버에서 검증하지 못했으므로
기본은 **명시적인 PC canonical 경로**입니다. 화면 폭으로 플랫폼을 추정하지 않습니다.
네이티브 모바일 `/m/` 경로를 실제로 사용하는 복사본에서만
`--native-platform mobile`을 명시합니다. 이 옵션은 미해석 장바구니 가상태그의
대체 경로를 고르며, 상세·주문·결제 템플릿을 변환하지 않습니다.

## 복붙 순서

운영 스킨이 아닌 **반응형 복사 스킨**인지 먼저 확인하고 14개 소스를 별도로
백업합니다. 기존 PC 전용·모바일 전용 스킨에 통째로 적용하는 패키지가 아닙니다.

1. 공통 CSS/JS: `apply/common.css`, `apply/common.js`를 해당 탭 전체에 붙여넣습니다.
   공통 JS 상단에 `dist/storefront.js`의 classic 사본과 네이티브 연결부가 **한 번**
   포함됩니다. 별도 모듈 태그나 같은 설정/초기화 코드를 추가로 덧붙이지 않습니다.
2. 헤더 1: `apply/header.1.html`, `.css`, `.js`를 각각 붙여넣습니다.
   로고·상단/사이드 메뉴는 같은 설정에서 나오며 검색 폼은 하나만 유지합니다.
3. 푸터 1: `apply/footer.1.html`, `.css`, `.js`를 각각 붙여넣습니다.
   회사·사업자·약관·고객센터/계좌 가상태그는 보존합니다. 위로 버튼은 하나입니다.
4. 메인: `apply/main.html`, `.css`, `.js`를 각각 붙여넣습니다.
   헤더·메뉴·푸터 include와 원본 상품 loop/가격·품절 가상태그를 보존합니다.
5. 분류: `apply/shopbrand.html`, `.css`, `.js`를 각각 붙여넣습니다.
   상품 loop는 유지하고 네이티브 `select_sort` 하나를 PC·모바일에서 사용합니다.

전체 원본 사본을 적용하는 경로와 아래 iframe 대안은 **함께 사용하지 않습니다**.
메인 HTML 일부만 교체하면서 기존 헤더/메인 JS를 남기면 검색·슬라이더가 이중
초기화되거나 메뉴·스크롤이 중복될 수 있습니다. 공통 CSS/헤더는 다른 페이지에도
영향을 주므로 복사본의 상세·로그인·장바구니까지 확인해야 합니다.

## 별도 iframe 대안

네이티브 메인 사본 대신 기존 외부 고객 프론트를 넣는 선택 경로입니다.
실제 HTTPS 호스팅 주소가 정해진 뒤에만 다음처럼 생성합니다. 아래 주소는 설명용이며
배포 주소로 사용하지 않습니다.

```powershell
python -B integration-responsive/build.py --native-platform pc --frontend-url "https://YOUR-ACTUAL-HOST/"
```

또는 `PINKROCKET_FRONTEND_URL` 환경 변수를 설정합니다. HTTPS, 명시적인 마지막 `/`,
인증정보·쿼리·fragment 없는 주소만 허용합니다. 출력 `OPTIONAL_MAIN_IFRAME.txt`는
기존 `integration-main/build.py`의 공유 상세 URL·찜 모듈·계정 브리지를 재사용합니다.
알 수 없는 Cloudflare 주소는 기본값으로 넣지 않습니다. 네이티브 `apply/main.*`와
동시에 붙이지 말고, 메인 전용 HTML 교체 및 CSS/JS 충돌 정리는 별도 검수합니다.

## 갤러리 수집은 별도

`GALLERY_MAIN_COLLECTOR.html`은 복사본 메인에서 **렌더된 실제 데이터만 읽기 위한**
별도 코드입니다. `<template>` 안에 상품 ID와 이미지 URL을 `data-*` 속성으로만
출력합니다. `<img>`, `src`, 외부 스크립트, 요청 함수가 없어 이 코드 자체의
숨은 이미지 다운로드는 없습니다. 원래 페이지의 기존 이미지 요청은 그대로입니다.

- 범위는 원본 메인의 신상 80·특별 6·베스트 200 루프뿐입니다. 합산 최대 286칸이며
  중복 상품·서버 제한에 따라 실제 수는 줄어듭니다. **전체 2,379개 상품 수집이 아닙니다.**
  add28/29/26/27 진열 슬롯과 메인에 없는 상품은 포함하지 않습니다.
- 각 상품의 `list_photo_gallery`가 있으면 URL 순서대로, 없으면 대표 `image_s`
  한 개를 출력합니다. 상세 페이지의 `multi_image_list`와 다릅니다.
- 메인 신상·특별 태그는 공식 메인 예제, 베스트 태그는 공식 분류 예제와 원본 메인
  best loop를 조합했습니다. 이 반응형 복사본 서버에서의 치환은 아직 미확인입니다.
  미해석 `<!--/.../-->`가 남으면 수집 성공으로 보지 않고 importer가 전체 거부합니다.
- 공식 지원 버전·모바일 전용 포토갤러리/PC fallback 조건을 실제 복사본에서 확인합니다.
  이미지 파일명 뒤에 `_2`, `_3`을 붙여 URL을 만들지 않습니다.
- 실제 렌더 후 컨테이너는 `data-product-images-id="상품ID"`, 내부 요소는
  `data-product-image-url="실제URL"`입니다. 원본 collector 파일을 그대로 importer에
  넣지 말고, 메이크샵이 가상태그를 치환한 HTML을 읽어야 합니다.

## 검수와 복구

- 390/800/1280px 및 실제 터치 기기에서 배너·메뉴·검색·정렬·푸터·가로 넘침을 확인합니다.
- 배너는 슬라이드당 이미지 한 개가 기본인지, 모바일 전용 자산이 필요할 때만
  `<picture>`를 쓰는지, 반복 `apply()`가 DOM/폼/슬라이더를 복제하지 않는지 확인합니다.
- PC·모바일에서 같은 설정의 이름·목적지·배너 순서가 보이는지 확인합니다.
- 검색 입력·제출은 원본 `form_search`, 정렬은 원본 `select_sort`를 사용합니다.
  로그인/가격/품절/찜/장바구니 결과를 정적 파일만으로 성공 판정하지 않습니다.
- 헤더 높이·검색 열기/닫기·메뉴 닫기·장바구니·맨 위로 버튼의 포커스와 스크롤을 확인합니다.
- 상품의 원본 사진/가격/loop, 상세·옵션·로그인·주문·결제를 유지하는지 확인합니다.
- 미제공 원본: `include_menu(1)` 소스, 전체 head/문서 설정, 반응형 상세·로그인·주문·결제
  템플릿과 실제 스킨 라우팅입니다. 이 패키지가 쇼핑몰 전체 전환 완료를 뜻하지 않습니다.
- 되돌릴 때는 복사본의 14개 탭을 모두 백업본으로 복원합니다. 운영 대표 디자인은
  사용자 검수와 별도 적용 결정 전까지 바꾸지 않습니다.

자동 검사는 소스 보존·생성 일치·DOM·통신 경계를 검사합니다. 실제 메이크샵 서버
렌더링·계정 저장·결제·실기기 터치 검수와는 구분합니다.
