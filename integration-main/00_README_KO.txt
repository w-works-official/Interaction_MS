PINKROCKET 메이크샵 복사 스킨 메인 iframe 연결 — 확인용

이 파일은 PC·모바일 복사 스킨의 메인 HTML을 전체 교체하는 셸입니다.
기존 메인 아래에 추가하는 integration-poc 시험 파일과 사용 방법이 다릅니다.
운영 스킨과 실제 주문·결제 페이지를 교체하는 파일이 아닙니다.

1. 먼저 확인하세요

- 메이크샵의 현재 PC 스킨과 모바일 스킨을 각각 복사하고 복사본인지 확인합니다.
- 복사본의 기존 메인 HTML을 각각 별도 파일로 백업합니다.
- 원래 공통 CSS·메인 CSS·JS 탭과 헤더/푸터 소스는 수정하지 않습니다.
- 기존 메인 HTML을 지우고 아래 해당 파일의 전체 내용을 붙여넣습니다.
  PC 메인: 01_MAIN_IFRAME_PC.txt
  모바일 메인: 02_MAIN_IFRAME_MOBILE.txt
- 두 파일에는 같은 반응형 외부 프론트를 사용하지만 부모의 플랫폼은 각각
  data-platform="pc", data-platform="mobile"로 명시되어 있습니다.
- 복사 스킨의 메인 HTML 저장 후 그 복사본의 미리보기로만 확인합니다.
  운영 스킨 적용·대표 디자인 변경 버튼은 누르지 않습니다.
- 되돌리려면 복사본 메인 HTML을 백업한 원래 내용으로 복원합니다.

2. 먼저 배포해야 하는 코드

- dist/의 새 iframe 브리지가 배포되어 있어야 통신과 실제 기능 요청을 받습니다.
- parent.js가 외부 iframe 주소와 통신 설정을 구성합니다. 프론트 주소를 변경한
  경우 parent.js를 수정한 뒤 생성기를 다시 실행합니다.
- 외부 프론트는 HTTPS로 제공해야 합니다. GitHub Pages 주소는 화면 확인용입니다.
  상업 운영 호스팅이나 운영 메이크샵 적용은 이 파일의 범위에 포함되지 않습니다.
- 원본 메인 상품 목록에 의존하던 최대 3개 상품 시험은 integration-poc에 남아
  있으며, 이 교체 셸과 혼용하지 않습니다.

3. 미리보기에서 확인할 항목

- 처음에는 연결 상태가 표시되고 통신 준비를 확인할 때까지 상품 조작을 막습니다.
  연결 안내가 사라지지 않으면 최신 dist/ 배포 여부와 허용된 부모 주소를 확인하고
  새로고침합니다. 연결이 확인되지 않은 상태에서 기존 로컬 데모 버튼을 대신 누르지 않습니다.
- PC와 모바일 각각의 복사본에서 로고·검색·탭·상품 목록이 중복 없이 나타나는지
  확인합니다. 기존 메이크샵 헤더·푸터가 자동 주입되는 경우 이 메인에만 적용되는
  셸의 CSS가 해당 시각 요소를 숨깁니다. 다른 페이지의 공통 CSS는 바꾸지 않습니다.
- 부모의 기존 최소폭과 메인 여백을 이 셸이 있는 페이지에서만 해제합니다.
  iframe은 부모 뷰포트 높이(100dvh, 미지원 시 100vh)를 사용하고 내부에서 스크롤합니다.
- 2→3→4열, 사진 3:4, 탭 이동과 목록 위치 복원, 무한 스크롤·더 보기, 사진 전환,
  필터·상세 팝업과 모바일 하단 메뉴를 확인합니다.
- 부모와 자식이 각각 스크롤되거나 가로로 넘치지 않는지 확인합니다.
  모바일 주소창 변화·키보드·안전 영역 동작은 실제 기기에서 추가 확인합니다.
- iframe 높이를 콘텐츠 전체 높이로 늘리는 방식은 사용하지 않습니다.
  현재 프론트는 자식 뷰포트의 sticky/fixed 요소와 window.scrollY를 사용합니다.

4. 실제 메이크샵 기능과 성공 확인

- 상품 사진·이름은 상품 정보 목업을 거치지 않고 패널 안 실제 메이크샵 상세를 엽니다.
  상품 상세의 사진·설명·가격·옵션은 메이크샵 원본 화면 그대로 표시합니다.
  기본 동작은 현재 패널이며 새 창 링크는 표시·로그인 문제가 있을 때만 이용합니다.

- 상세 URL은 상품 ID와 부모 플랫폼으로 생성하며 실제 상세·로그인·옵션·가격·품절
  검증은 메이크샵 원래 화면에서 처리합니다.
- 장바구니는 열린 실제 상세 안에서 사용자가 옵션과 수량을 선택하고 원래 버튼을
  직접 누릅니다. 셸 바깥에 대신 실행하는 장바구니 버튼은 만들지 않습니다.
- 찜·장바구니 버튼에 요청을 보냈거나 상세가 열렸다는 사실은 계정 저장 성공을
  의미하지 않습니다. 실제 찜 목록·장바구니에서 상품 ID·옵션·수량을 확인합니다.
- 로그인 필요, 다른 도메인으로 이동, iframe 차단이나 스킨 구조 변경 등이 있으면
  결과를 추측하거나 자동 재전송하지 말고 원본 상세를 직접 열어 확인합니다.
- 장바구니 목록 주소는 메이크샵의 전역 link_basket 가상태그를 해석한 같은 출처의
  링크를 사용합니다. 가상태그가 해석되지 않았다면 목록 주소를 추측해 이동하지 않습니다.
- 상세 창은 닫기 버튼으로 닫을 수 있습니다. 메이크샵 내부의 실제 화면과 팝업은
  자체 동작을 사용합니다. 키보드 닫기와 초점 복귀는 생성된 부모 코드에서 처리합니다.
- 생성·정적 검사만으로 실제 HTTP 계정 동작을 검증했다고 말할 수 없습니다.
  복사본 미리보기와 실제 계정에서의 버튼 동작·저장 결과는 사용자가 확인해야 합니다.

로컬 브라우저 검증에서 남은 항목

- 실제 Chrome의 로컬 모의 환경에서 연결, 첫 상세 로드, 옵션 A·수량 2의 모의 버튼
  클릭과 원본 상세로 이동하는 대체 경로를 확인했습니다. 이 환경은 원본 계정과 무관합니다.
- 반복해서 다른 상품을 열 때 상세 iframe이 대기 상태에 남는 경우도 관찰했습니다.
  요청마다 새 iframe을 만들고 이전 요청을 무효화하지만, 이 현상의 해결을 확정하지는
  않았습니다. 실제 복사 스킨 미리보기에서 반복 진입을 확인해야 합니다.
- 상세가 비거나 시간 초과 안내가 나오면 '원본 상품 상세 열기'를 사용합니다.
  이 링크는 해당 상품 ID와 PC/모바일 경로로 메이크샵 원본 상세에 직접 이동합니다.
- 단독 프론트는 실제 표시가 확인된 https://pink-rocket.com 주소에 공유 URL 함수의
  경로·쿼리를 붙입니다. 로컬 Chrome 패널 안에서 실제 상품 2084924의 원본 제목,
  사진·가격·옵션 영역과 #cartBtn을 읽기 전용으로 확인했습니다. 실제 원본 버튼은
  누르지 않았으며 계정 저장·실제 복사 스킨·휴대폰 실기기 검수는 남아 있습니다.
- 공개 응답의 X-Frame-Options/CSP나 직접 소스의 초기 프레임 차단은 확인되지 않아
  초기 빈 상태를 메이크샵의 차단이라고 단정하지 않습니다.
- 현재 파일은 연결 검증용이며 실제 계정 연동 완료본으로 간주하지 않습니다.

5. 운영자 저장 제한

- 공용 저장소는 연결하지 않았습니다. 초안·목업 공개·찜/장바구니 데모 데이터는
  브라우저 로컬 저장입니다. 실제 메이크샵 계정 상태와 별개입니다.
- 브라우저는 외부 iframe의 저장소를 사이트별로 분리하거나 차단할 수 있습니다.
  외부 프론트를 직접 연 운영자 화면과 메이크샵 안의 iframe이 항상 같은 로컬
  초안/공개본을 읽는다고 가정하지 마세요. 필요한 경우 같은 문맥에서 구성을
  가져오고 미리보기 결과를 확인합니다. 브라우저 간 자동 공유는 구현하지 않았습니다.

6. 개발·재생성

프로젝트 루트에서 다음 명령을 실행합니다.
  python integration-main/build.py

다른 작업 폴더에서는 build.py의 절대 경로를 지정합니다.

생성기는 스크립트 위치를 기준으로 dist/model.js의 실제 makeshopDetailUrl() 함수를
부모 코드에 포함합니다. PC/모바일 txt와 outputs/makeshop-main-preview/의 동일 파일,
이 안내서, outputs/pinkrocket_makeshop_main_preview.zip을 생성합니다.
같은 소스로 반복 생성하면 TXT와 ZIP 내용이 같습니다. outputs는 Git에 포함하지 않습니다.

이 생성기는 로컬 파일만 만듭니다. 메이크샵·GitHub·외부 호스팅에 저장하거나 배포하지 않습니다.
